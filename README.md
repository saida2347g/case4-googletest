# Кейс-задача № 4: GoogleTest

Интерфейсы очереди, максимальной кучи и бинарного дерева поиска, а также
36 модульных тестов на C++17 с GoogleTest. Алгоритмы структур данных
не реализованы в соответствии с условием задания.

## Принятые контракты

| Класс | Метод | Ожидаемое поведение |
|---|---|---|
| Queue | void push(int) | Добавляет элемент в конец очереди |
| Queue | int pop() | Удаляет и возвращает первый добавленный элемент (FIFO) |
| Heap | void push(int) | Добавляет элемент, сохраняя свойства максимальной кучи |
| Heap | int pop() | Удаляет и возвращает максимальный элемент |
| BinaryTree | void push(int) | Добавляет ключ в бинарное дерево поиска; повторный ключ игнорируется |
| BinaryTree | bool pop(int) | Удаляет заданный ключ; true при удалении, false при отсутствии |
| BinaryTree | bool search(int) const | Возвращает признак наличия ключа, не меняя дерево |

В Queue и Heap повторяющиеся значения сохраняются. Вызов pop() для пустой
очереди или кучи должен выбрасывать std::out_of_range, не меняя состояние.
Для дерева выбрано удаление по ключу: условие задания не задаёт сигнатуру pop.
Тип элементов — int. Копирование объектов запрещено, его проверка не входит
в задание. Конструкторы и деструкторы также только объявлены.
Закрытый указатель Impl резервирует место для будущей реализации, не задавая алгоритм.

## Файлы

- include/structures.hpp — объявления классов и контракты методов.
- tests/queue_test.cpp — 10 тестов очереди.
- tests/heap_test.cpp — 10 тестов максимальной кучи.
- tests/binary_tree_test.cpp — 16 тестов дерева поиска.
- CMakeLists.txt — сборка тестовых объектных файлов и подключение GoogleTest.
- .github/workflows/compile.yml — проверка компиляции через GitHub Actions.

## Покрытие

Для очереди и кучи: пустое состояние, один элемент, порядок извлечения,
дубликаты, отрицательные числа, ноль, INT_MIN/INT_MAX, чередование операций,
повторное использование, независимость экземпляров и 1000 элементов.
Для дерева: поиск и удаление отсутствующего ключа, вставка, неизменность
при поиске через const-ссылку, дубликаты, удаление листа, узла с левым или
правым потомком, узла с двумя потомками, корня, повторное использование,
сохранение остальных ключей, граничные значения и последовательные вставки.

## Сборка интерфейсов и тестов

Нужны CMake 3.16+, компилятор C++17 и доступ к GitHub для загрузки GoogleTest.
При наличии установленного пакета GTest используется он; иначе CMake
загружает закреплённую ревизию, указанную в официальном примере GoogleTest.

```sh
cmake -S . -B build
cmake --build build --target contract_tests
```

Это компиляция тестов в объектные файлы, а не выполнение тестов.
Отсутствие реализаций не позволяет скомпоновать исполняемый файл и проверить
поведение структур. В проекте нет подменяющих реализацию заглушек, моков
или искусственно пропущенных тестов. CI проверяет только компиляцию.

## Запуск после добавления реализаций

Этот шаг не требуется для сдачи интерфейсов. Если позднее методы классов
будут определены в src/structures.cpp, включая Impl, конструкторы и
деструкторы, можно использовать:

```sh
cmake -S . -B build-run -DIMPLEMENTATION_SOURCES=src/structures.cpp
cmake --build build-run
ctest --test-dir build-run --output-on-failure
```

Нужно реализовать именно объявленные классы в пространстве имён coursework.
Тесты используют проверки состояния и результатов; внутреннее устройство
контейнеров не проверяется.

## Размещение на GitHub

1. Создать репозиторий case4-googletest в своём аккаунте GitHub.
2. Загрузить содержимое этой папки в корень репозитория, сохранив каталоги.
   Папка .github скрытая: при ручной загрузке необходимо включить и её.
3. В качестве ответа на задание указать URL созданного репозитория.

## Выполненная локальная проверка

Объявления интерфейсов проверены компилятором g++ в режиме C++17.
Проверены число тестов и структура архива. Компиляция тестовых файлов с
GoogleTest в среде подготовки не выполнялась: CMake и GoogleTest здесь
не установлены. Запуск поведенческих тестов требует реализации методов.
